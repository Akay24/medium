# Article Quality Checklist

## Research
- [ ] Important claims have relevant, accessible sources.
- [ ] Sources support the claims they are attached to.
- [ ] Version-dependent behavior is qualified.
- [ ] Evidence gaps and inaccessible sources are disclosed.

## Technical
- [ ] Core mechanism is explained accurately.
- [ ] Trade-offs and failure modes are included.
- [ ] Assumptions are explicit.
- [ ] Code examples are coherent and have stated execution status.
- [ ] No fabricated benchmarks or test results.

## Editorial
- [ ] Article is concise, punchy, and helpful (~1,200 to 1,800 words).
- [ ] No academic bloat, generic intros, or repetitive conclusions.
- [ ] Code examples are concrete, verified, and practical.
- [ ] Interview connections and trade-offs provide immediate actionable value.

## Visuals
- [ ] Exactly 3 visual assets present (1 cover hero + 2 core technical diagrams).
- [ ] Zero raw Mermaid code blocks or collapsible `<details>` blocks.
- [ ] Diagrams visually convey the most important request lifecycle and failure mode/mechanism.
- [ ] Visuals are high-resolution, rich aesthetic, and ready for Medium drag-and-drop.

## Publication
- [ ] Subtitle and excerpt are accurate.
- [ ] Tags are relevant and within current platform limits.
- [ ] Reading time is based on the completed draft.
- [ ] Navigation links are real or clearly marked placeholders.
- [ ] References are included.
- [ ] Remaining manual actions are listed.

## Final status
Choose one:
- PASS: Ready for human editorial review.
- NEEDS REVIEW: Specific issues remain; list them.
- FAIL: Material accuracy or completeness problems block publication.
